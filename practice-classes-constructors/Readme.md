## Що потрібно знати

- У списку ініціалізації задають початкові значення полів. Поля створюються в порядку оголошення в класі та знищуються у зворотному порядку.
- `T copy(original);` і `T copy = original;` створюють новий об’єкт із наявного. `copy = original;` після оголошення `copy` викликає оператор присвоєння.
- Деструктор локального об’єкта викликається автоматично після виходу з області видимості, зокрема під час поширення винятку. У завданнях із трасуванням перед запуском випишіть порядок усіх викликів.
- Якщо клас сам володіє динамічним масивом, проста копія вказівника залишить двом об’єктам одну адресу. Для незалежних власників потрібні окремі масиви. У прикладному коді типи на кшталт `std::vector` зазвичай беруть керування пам’яттю на себе.

### Завдання 20 — Коли знищується тимчасовий об’єкт

Створіть `Trace` із міткою та ознакою того, що об’єкт створено конструктором копіювання. Конструктори друкують `+ мітка` або `+ copy мітка`, а деструктор друкує відповідний рядок із `-`. Функція `MakeTrace(const std::string& label)` повертає за значенням через `return Trace(label);`. Функція `Inspect(const Trace& trace)` виводить `inspect мітка`.

Введіть дві мітки. Першою через `MakeTrace` ініціалізуйте іменований локальний об’єкт. Другу використайте в `Inspect(Trace(мітка));`. Виведіть `after inspect` і явно створіть копію першого об’єкта.

Вираз `Trace(label)` у `return` є prvalue. У C++20 він безпосередньо ініціалізує результат функції, а результат `MakeTrace` одразу будує іменований об’єкт. Конструктор копіювання викликається в окремій операції, коли створюєте копію з іменованого об’єкта. Тимчасовий аргумент `Inspect` знищується наприкінці повного виразу з викликом.

**Ввід**

```text
named temporary
```

**Вивід**

```text
+ named
+ temporary
inspect temporary
- temporary
after inspect
+ copy named
- copy named
- named
```
