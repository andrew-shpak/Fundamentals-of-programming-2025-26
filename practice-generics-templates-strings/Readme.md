## Шкала складності

Оцінки орієнтовні й відносні до рівня цього практикуму. Вважаємо, що студент уже знає змінні, умови, цикли, масиви та звичайні функції. Оцінюємо самостійне розв’язання за умовою, до перегляду реалізації; це не оцінка часу виконання програми чи її алгоритмічної складності.

| Рівень | Назва | Що зазвичай потрібно |
| --- | --- | --- |
| 1/5 | Дуже легко | Кілька базових операцій або один простий цикл. |
| 2/5 | Легко | Поєднання базових прийомів, проста робота з індексами, посиланнями чи класом. |
| 3/5 | Середньо | Вкладені цикли, допоміжний стан або кілька пов’язаних граничних випадків. |
| 4/5 | Складно | Узгодження кількох індексів чи станів, типів або складніших механізмів шаблонів. |
| 5/5 | Підвищена складність | Алгоритм із нетривіальним правилом підтримки стану та вимогою ефективності; найскладніший рівень цього практикуму. |

Біля кожного із 30 завдань зазначено рівень і конкретну причину оцінки. Однаковий рівень у різних розділах означає приблизно подібне навчальне навантаження. Попередній досвід із шаблонами або рядками може змінити особисте сприйняття складності; порядок і нумерацію завдань збережено.

## Як пов’язані generics і templates

Узагальнене програмування — підхід: один алгоритм або структура даних працює з різними типами. Шаблони C++ — мовний механізм цього підходу. Тому перший розділ присвячено **шаблонам функцій**, другий — **шаблонам класів/структур**, параметрам місткості й спеціалізації. Це не різні мови чи несумісні технології.

Розділ рядків є добіркою з [наявних 30 задач](../lab-sting/Readme.md) з готовими розв’язаннями. Другий розділ розширює тему з [лабораторної про матриці](../lab-matrix/Readme.md): там `Matrix<T>` зберігає дані без методів, тут окрема вправа навчає шаблонних методів та розмірів у типі. Вимоги старих лабораторних залишаються чинними для їхніх завдань.

## Робота із завданнями

1. Прочитайте умову й спробуйте написати власний варіант.
2. Відкрийте посилання «Повна реалізація» та порівняйте алгоритм.
3. Скомпілюйте окремий файл і перевірте приклад із `samples/`.
4. Перевірте порожні дані, повторення, межі місткості й неправильні параметри. Для шаблонів змініть тип або місткість без переписування реалізації.

З кореня репозиторію:

```sh
c++ -std=c++20 -Wall -Wextra -Werror -pedantic \
  practice-generics-templates-strings/generics/src/task01_swap.cpp \
  -o /tmp/generic-swap
printf '3 8\n' | /tmp/generic-swap
```

Очікуваний результат:

```text
8 3
```

Для рядків важливо передавати справжні порожні рядки та зберігати пробіли:

```sh
c++ -std=c++20 -Wall -Wextra -Werror -pedantic \
  practice-generics-templates-strings/strings/src/task01_normalize_spaces.cpp \
  -o /tmp/string-spaces
printf '  one   two  three  \n' | /tmp/string-spaces
```

## Автоматична перевірка

Потрібні Python 3 та компілятор C++20. З кореня репозиторію виконайте:

```sh
python3 practice-generics-templates-strings/verify.py
```

Скрипт компілює всі 30 програм із попередженнями як помилками та AddressSanitizer/UndefinedBehaviorSanitizer, порівнює приклади й граничні випадки з `cases.json`, перевіряє узгодженість документації та транскриптів. Додатково він компілює 10 алгоритмів із `Value = double` та перевіряє шаблонні типи з іншими параметрами, незмінність стану при невдалих операціях і повторне використання кільцевого буфера. Бінарні файли створюються в тимчасовій директорії поза репозиторієм.

Інший компілятор можна вибрати через `CXX`, наприклад `CXX=clang++ python3 practice-generics-templates-strings/verify.py`. Якщо компілятор не підтримує санітайзери, використайте `--no-sanitizers`; такий запуск перевіряє результати без динамічної діагностики пам’яті.
